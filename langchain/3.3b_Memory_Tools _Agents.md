### 1. Memory

### What is Memory?

Memory allows an AI application to remember information from previous interactions and use it in future responses.

Without memory:

**User:** My name is Raj.

**AI:** Nice to meet you, Raj.

**User:** What is my name?

**AI:** I don't know.

With memory:

**AI:** Your name is Raj.

### Why Memory Exists

LLMs are stateless by default.

Every API call is independent.

Memory provides continuity across interactions.

### Real-World Analogy

Imagine talking to a doctor.

* Without memory → The doctor asks your name and history every visit.

* With memory → The doctor remembers your previous visits and medications.

AI assistants need the same capability.

### Types of Memory

| Memory Type         | Remembers                        |
| ------------------- | -------------------------------- |
| Conversation Memory | Entire chat history              |
| Window Memory       | Last N messages                  |
| Summary Memory      | Compressed conversation summary  |
| Persistent Memory   | Long-term user information       |
| Vector Memory       | Semantic memories via embeddings |

### Simple Conversation Memory

### Runnable Example

Python

```
from langchain_core.messages import HumanMessage, AIMessage
from langchain_openai import ChatOpenAI

model = ChatOpenAI(model="gpt-4.1-mini", temperature=0)

# In-memory conversation history
history = []

def chat(user_input: str):
    # Add user message to history
    history.append(HumanMessage(content=user_input))

    # Send entire history to model
    response = model.invoke(history)

    # Store AI response
    history.append(AIMessage(content=response.content))

    return response.content

print(chat("My name is Raj."))
print(chat("What is my name?"))
```

### Expected Output

```
Nice to meet you, Raj.
Your name is Raj.
```

### Window Memory

Instead of storing the entire conversation:

Python

```
WINDOW_SIZE = 4

history = history[-WINDOW_SIZE:]
```

### Why Use It?

* Reduces token usage

* Improves performance

* Prevents context overflow

### Summary Memory

Long conversations become expensive.

A summary memory compresses old messages.

```
User discussed:
- Learning LangChain
- Building a RAG system
- Using Ollama locally
```

The summary replaces dozens of earlier messages.

### Persistent Memory

Store important information in a database.

### Example

Python

```
user_profile = {
    "name": "Raj",
    "preferred_model": "Ollama",
    "goal": "Become a LangChain expert"
}
```

This survives application restarts.

### When to Use Memory

Use memory for:

* Personal assistants

* Tutoring systems

* Customer support

* Long-running workflows

* Multi-step reasoning tasks

### When NOT to Use Memory

Avoid memory for:

* One-shot API calls

* Stateless microservices

* Privacy-sensitive interactions

* High-throughput batch jobs

### Advantages

* Natural conversations

* Personalization

* Better task continuity

* Reduced repeated questions

### Limitations

* Higher token cost

* Possible context pollution

* Privacy concerns

* Requires memory management

Best Practices

* Store only relevant information

* Use window memory for chatbots

* Use summary memory for long sessions

* Persist user preferences separately from conversation history

Common Mistakes

* Storing every message forever

* Mixing memories between users

* Forgetting to trim old history

* Persisting sensitive data without encryption

### 2. Tools

### What is a Tool?

A Tool is a function that an LLM can call to interact with the outside world.

Examples:

* Search the web

* Query a database

* Read a PDF

* Execute Python code

* Send an email

* Get weather information

Without tools, an LLM can only generate text.

With tools, it can perform actions.

### Real-World Analogy

Think of a chef.

* Without tools → Can only describe recipes.

* With tools → Can actually cook.

Tools give AI capabilities beyond text generation.

### Creating a Tool

### Install

Bash

```
pip install -U langchain langchain-openai
```

### Runnable Example

Python

```
from langchain_core.tools import tool

@tool
def multiply(a: int, b: int) -> int:
    """Multiply two numbers."""
    return a * b

print(multiply.invoke({"a": 6, "b": 7}))
```

### Expected Output

```
42
```

### Why the Docstring Matters

The LLM reads:

Python

Run

```
"""Multiply two numbers."""
```

This description helps the model decide when to use the tool.

### Multiple Tools

Python

```
from langchain_core.tools import tool

@tool
def add(a: int, b: int) -> int:
    """Add two numbers."""
    return a + b

@tool
def subtract(a: int, b: int) -> int:
    """Subtract two numbers."""
    return a - b

tools = [add, subtract]
```

The agent can choose between them dynamically.

### 3. Agents

### What is an Agent?

An Agent is an LLM that can:

* Reason about a task

* Decide which tools to use

* Execute tools

* Observe results

* Continue reasoning until it reaches an answer

This is the core of autonomous AI behavior.

### Agent vs Chain

| Chain             | Agent                       |
| ----------------- | --------------------------- |
| Fixed sequence    | Dynamic decisions           |
| Predictable flow  | Adaptive flow               |
| No tool selection | Chooses tools automatically |
| Easier to debug   | More flexible               |

### Real-World Analogy

Chain = Following a recipe exactly.

Agent = A chef deciding:

* Which ingredients to use

* Which tools are needed

* Whether to adjust the recipe

Agents add decision-making.

This is often called the Thought → Action → Observation loop.

### ReAct Pattern

The most common agent architecture.

```
Thought: I need to calculate 25 × 19.
Action: multiply(a=25, b=19)
Observation: 475
Thought: I have the result.
Final Answer: 475
```

### Runnable Example

Python

```
from langchain_openai import ChatOpenAI
from langchain.agents import create_agent
from langchain_core.tools import tool

@tool
def multiply(a: int, b: int) -> int:
    """Multiply two numbers."""
    return a * b

model = ChatOpenAI(model="gpt-4.1-mini", temperature=0)

agent = create_agent(
    model=model,
    tools=[multiply]
)

response = agent.invoke({
    "messages": [
        {"role": "user", "content": "What is 23 multiplied by 17?"}
    ]
})

print(response["messages"][-1].content)
```

### Expected Output

```
23 multiplied by 17 is 391.
```

The agent decides to use the `multiply` tool automatically.

### Multi-Step Agent

Request:

"What is the square of (15 + 5)?"

Possible execution:

```
1. add(15, 5) → 20
2. square(20) → 400
3. Return answer
```

The agent orchestrates multiple tools.

### Advantages

* Flexible problem solving

* Dynamic tool usage

* Handles unknown workflows

* More human-like interaction

### Limitations

* Less predictable

* Higher token usage

* More expensive

* Harder to debug

### When to Use Agents

Use agents when:

* The workflow is unknown in advance.

* Multiple tools may be needed.

* The number of steps varies.

* The assistant must decide dynamically.

### When NOT to Use Agents

Prefer chains when:

* The workflow is fixed.

* You need deterministic behavior.

* Latency is critical.

* Costs must be minimized.

Best Practices

* Start with chains; add agents only when necessary

* Use small, well-defined tools

* Log every tool call for debugging

* Set execution limits and timeouts

Common Mistakes

* Using agents for simple tasks

* Giving tools ambiguous descriptions

* Allowing infinite tool loops

* Ignoring error handling

### Interview Questions

### Q1. What is the difference between memory and a vector database?

Memory: Stores conversation state for continuity.

Vector DB: Stores semantic embeddings for retrieval.

### Q2. Why are tools important for agents?

They allow the agent to interact with external systems and perform actions that pure text generation cannot accomplish.

### Q3. When should you choose a chain instead of an agent?

When the workflow is fixed, deterministic, cheaper to execute, and easier to debug.

### Q4. What is the ReAct pattern?

A reasoning framework where the model alternates between Thought, Action, and Observation until it reaches a final answer.
